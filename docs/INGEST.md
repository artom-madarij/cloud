Приймання даних від IoT-датчиків

Загальний принцип роботи

Для приймання даних використовую Amazon API Gateway та AWS Lambda.

Емулятор надсилає кожне вимірювання окремим HTTP POST-запитом на API Gateway. Після цього запит обробляє Lambda-функція `lamp-store-iot-ingest`.

Функція перевіряє ключ доступу та правильність отриманих даних. Якщо все коректно, повідомлення надсилається до Amazon SQS.

Для цього використовується черга `lamp-store-iot-measurements`.

Важливо, що функція приймання не записує дані безпосередньо в базу. Вона лише перевіряє повідомлення та додає його до черги. Подальшу обробку виконує інша Lambda-функція.

Формат повідомлення

Кожне повідомлення містить такі дані:

- `sensor_id` — ідентифікатор датчика.
- `sensor_type` — тип датчика.
- `value` — отримане значення.
- `unit` — одиниця вимірювання.
- `location` — координати датчика (`lat` і `lon`).
- `measured_at` — дата та час вимірювання у форматі UTC ISO 8601.

Приклад повідомлення:

{
  "sensor_id": "temperature-01",
  "sensor_type": "temperature",
  "value": 29.53,
  "unit": "°C",
  "location": {
    "lat": 49.8397,
    "lon": 24.0297
  },
  "measured_at": "2026-11-16T08:53:52.160Z"
}

Перевірка запиту

Для захисту API використовую ключ доступу, який передається в заголовку `x-api-key`.

Перед додаванням повідомлення до черги Lambda перевіряє ключ та наявність обов'язкових полів.

Якщо ключ неправильний, запит відхиляється. Також відхиляються повідомлення з відсутніми або некоректними даними.

Для успішного запиту API повертає код `202 Accepted` та ідентифікатор повідомлення в SQS.

Якщо дані не пройшли перевірку, повертається `400 Bad Request`. Для запиту з неправильним ключем повертається `401 Unauthorized`.

Перевірка роботи API

Для тестування використав команду `curl`:

```bash
INGEST_URL="$(terraform output -raw iot_ingest_url)"

curl -i -X POST "$INGEST_URL" \
  -H "Content-Type: application/json" \
  -H "x-api-key: $TF_VAR_ingest_api_key" \
  -d "{
    \"sensor_id\": \"test-sensor-001\",
    \"sensor_type\": \"temperature\",
    \"value\": 25.5,
    \"unit\": \"°C\",
    \"location\": {
      \"lat\": 49.8397,
      \"lon\": 24.0297
    },
    \"measured_at\": \"$(date -u +%Y-%m-%dT%H:%M:%S.000Z)\"
  }"
```

Під час перевірки отримав відповідь `202 Accepted`. Це означає, що запит пройшов перевірку та повідомлення було додано до SQS.

Використання Amazon SQS

Для передачі вимірювань між функціями використовую Amazon SQS.

Кожне вимірювання додається до черги окремим повідомленням. Lambda-функція обробки отримує повідомлення з черги та записує результат у MySQL.

Використання черги дозволяє розділити приймання та обробку даних. Наприклад, якщо повідомлень надходить багато, вони можуть тимчасово зберігатися в SQS, поки Lambda обробляє їх.

Також це дозволяє повторно обробити повідомлення у випадку помилки.

Результати перевірки

Під час тестування перевірив надсилання повідомлень через API Gateway.

Отримав такі результати:

- Коректний запит приймається з кодом `202`.
- Повідомлення додається до Amazon SQS.
- Запит без обов'язкових даних відхиляється.
- Запит із неправильним ключем доступу відхиляється.

Отже, вдалося налаштувати приймання вимірювань через REST API та передачу повідомлень до Amazon SQS для подальшої обробки.
