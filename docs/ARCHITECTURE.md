Архітектура проєкту

Загальний опис

У цій лабораторній роботі реалізував систему для збору, обробки та збереження даних від IoT-датчиків за допомогою serverless-сервісів AWS.

Для тестування використовую локальний емулятор, який генерує дані трьох типів датчиків: температури, вологості та освітленості.

Отримані вимірювання надсилаються до AWS через REST API. Далі вони проходять перевірку, потрапляють у чергу та обробляються окремою Lambda-функцією.

Хмарна архітектура

Основний шлях передавання даних:


IoT Emulator -> Amazon API Gateway -> AWS Lambda (Ingest) -> Amazon SQS -> AWS Lambda (Processor) -> Amazon RDS (MySQL)

Для отримання історії вимірювань використовується окремий маршрут:

Client -> Amazon API Gateway -> AWS Lambda (History) -> Amazon RDS (MySQL)


Основні компоненти

Емулятор датчиків:

Розташований у директорії `lab1/emulator/`. Генерує вимірювання трьох типів датчиків та надсилає їх через HTTP POST-запити. Для запуску також підготовлений Dockerfile.

Amazon API Gateway:

Приймає HTTP-запити від емулятора та передає їх до Lambda-функції. Для приймання вимірювань використовується маршрут `POST /measurements`.

Lambda Ingest:

Функція `lamp-store-iot-ingest` перевіряє ключ доступу та правильність отриманих даних. Після успішної перевірки додає повідомлення до Amazon SQS.

Amazon SQS:

Черга `lamp-store-iot-measurements` використовується для тимчасового зберігання вимірювань перед обробкою.

Lambda Processor:

Функція `lamp-store-iot-processor` отримує повідомлення з черги, визначає тип датчика, перевіряє значення та записує результат у MySQL.

Amazon RDS:

Для зберігання вимірювань використовую Amazon RDS з MySQL. Усі три типи датчиків зберігаються в таблиці `measurements`.

Lambda History:

Функція `lamp-store-iot-history` обробляє запити на отримання історії вимірювань. Вона виконує запит до MySQL та повертає результат у форматі JSON.

Безпека

Для перевірки запитів на приймання даних використовую ключ доступу, який передається через заголовок `x-api-key`.

Облікові дані для підключення до бази даних зберігаються в AWS Secrets Manager.

База даних RDS розміщена у приватній підмережі та не має публічного доступу. Lambda-функції, які працюють із базою, підключаються до неї через VPC.

Розгортання

Інфраструктура AWS створюється за допомогою Terraform.

Код Lambda-функцій розташований у директорії `lab1/functions/`, а конфігурація хмарних ресурсів — у `lab1/terraform/`.

Це дозволяє створювати та налаштовувати необхідні ресурси за допомогою конфігураційних файлів, а не вручну через AWS Console.

Результат

У результаті реалізовано систему, яка приймає вимірювання від трьох типів IoT-датчиків, передає їх через Amazon SQS, обробляє за допомогою AWS Lambda та зберігає в Amazon RDS.

Також реалізовано окремий REST API для отримання історії вимірювань конкретного датчика.
